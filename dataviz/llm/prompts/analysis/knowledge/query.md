- **Nothing runs while the user types or edits the builder.** Only Run (or Ctrl+Enter) reaches the database.
- A query tab has its own text, connection, database, builder and results. The open tab is filled with colour and carries its own ✎ rename, ⧉ duplicate and × close; double-click any tab to rename it.
- **Run** asks the server what the text does. A plain read runs at once. Anything else, including what cannot be parsed, shows a confirm listing each statement.
- **Results**: rows are saved on the server. Sort and filter work on the saved result, so they never query the database again. Several statements give several result tabs.
- **Export** (the results toolbar) saves the open result as CSV, Excel (.xlsx, up to 1,048,575 rows), Parquet, JSON, JSON Lines, TSV, YAML, a Markdown table or an HTML table (those two: the first 100,000 rows). The last format used is listed first. Every row of the saved result goes into the file, not only the rows on screen.
- **Joins** counts rows on both sides when the user asks: a Venn of what the join keeps and cuts, and a fan-out warning.
- **Cost** shows each step's share of the plan. It is an estimate and does not run the query.
- **Visual builder**: left-drag selects, right-drag moves the board, wheel zooms. Click a column to select it, a table header to show or hide it. Drag a column onto another table to join. Click a join label to change it, right-click a line to remove it. Click a column's type to CAST it: the Change type dialog shows the current type, common types as chips by group (Number, Text, Date and time, Yes / no), a field with suggestions for any other type, and the CAST it will write. + Column adds CASE WHEN, window functions or an expression. + Subquery adds a card. Filters holds WHERE, GROUP BY, HAVING and ORDER BY.
- **Table cards** open as wide as the table's full name (up to 560 px). The ‹ button on a card's header (or its menu) collapses it to 200 px, where a long name ends in …; › widens it again. **Right-click a card** (or the menu key / Shift+F10 on a focused card) for: Rename… (a short header name: only the card changes, the SQL still uses the real table and its alias), Use the table name, Collapse / Show the full name, Hide from / Show in results, Select all columns, Clear the columns, Remove from the builder. Names and collapsed cards are kept with the tab.
- The builder sits left (next to the object explorer, to drag tables onto it), the SQL editor right. × on the builder closes it for SQL-only work; **Builder** on the toolbar opens it again (remembered).
- Subqueries in FROM / JOIN, CTEs and `OPENQUERY(...)` are cards (SUB, CTE, REMOTE) with the columns their SQL names: their own SELECT list plus every column the outer query uses through the alias, so join lines show between them. A `SELECT *` card with nothing else known shows "all columns (*)". A join on several columns (`ON a.x = b.x AND a.y = b.y`) is drawn as several lines with one join type.
- Unjoined tables give one result each; joined tables share one.
- Typed SQL keeps the builder read-only until it runs; then the builder redraws. What it cannot hold (UNION, PIVOT, APPLY, recursive CTE, self join, a join condition other than column = column [AND ...]) locks it and names why, and the query still runs.
- Layout: Builder (show or hide it), Standard, Table on top, Table only. Dividers resize panels, the corner button fills the window, Esc restores.
- **The ◆ assistant and the editor**: the assistant is sent the open tab's SQL and its last error with every message (short SQL sits in its prompt; longer text through read_editor), checks and fixes it for this connection's syntax (check_sql: errors with line and column, a rewrite when it was written for another database, then the database's EXPLAIN; nothing runs). What it writes comes as a card: the SQL, the changes against the editor (+ green, − red), Apply, Apply in a new tab, Copy. Apply replaces the editor text in one step, so Ctrl+Z in the editor undoes it. Running stays with the user's Run.
