# design3: Command console

**Concept:** a dense, keyboard-first, table-first Data Center. One omnibar ("Search or ask… ⌘K") takes structured tokens (`tag:traffic`, `in:bucket/path`, `ext:jpg`) and plain language (⇧↵ sends it to the Assistant). A compact facet strip (format stacked bar + counts, tags, sources) sits over a sortable bucket table. A mono activity log sits under the table, and a keyboard-hint footer runs along the bottom of every screen. Opening a bucket gives a tree-table with a 440px right pane, used for the file preview or for the AI split pane.

- **img1:** overview with `tag:traffic` applied. Matching buckets are grouped on top and the other 8 are dimmed (H hides them). Columns: format badge, structure check (✓/✗ per required part), images, labels, classes, size, tags, source, updated, sessions. The Activity / Jobs / Problems console is underneath.
- **img2:** traffic-cams-2026 › images/train expanded in place as a thumbnail grid. It shows 4 selected images, a focused image (amber) and a label-count badge on each thumb. The preview pane has YOLO boxes drawn from the label `.txt`, whose lines are listed with the selected box's line highlighted, plus meta and "Used in sessions".
- **img3:** the same folder in "Names only" mode (size, dims, labels, status, modified, with status values such as no label, empty .txt and class id out of range). A tag editor popover is open on the train/ row. It shows the locked auto tags (format:yolo, split:train), removable tags, typeahead suggestions (one of them AI-suggested) and key hints.
- **img4:** the AI split pane. The conversation shows a clarifying question with count chips ("clean up"), a reasoned refusal with an alternative ("video dataset"), and then the current request. For that request, the read-only tool calls ran automatically as mono lines and the 38 matches are highlighted in the tree. The editable action checklist has one step unchecked, so the button reads "Run 3 actions ⌘↵".
- **img5:** after labels/ was moved out, the row badge reads Other (YOLO struck through) with a ✗ on lbl, and the change is logged in the console. A toast offers Undo ⌘Z. The "Send to session" modal is open: Visualize/Label, new or existing session, name, task type, a summary of the selected folders with totals, a warning that the "Other" bucket will be sent without boxes, and "Import new data…".
- **img6/img7:** img1 and img2 in the light theme. Only tokens.css colours are used, so the light theme needed no extra overrides.

**Strengths:** very high information density on a big monitor. One input handles filtering, navigation and AI. The structure-check column makes format detection explainable at a glance. Format breakage is visible in three places (badge, check, log). The AI plan is auditable (exact tool calls, per-step checkboxes, undo window). Everything works from the keyboard.

**Weaknesses:** it is intimidating for casual users, because tokens and mono text read like a terminal. The 13-column table needs width of about 1400px or more, and narrow screens must drop columns. Dimming non-matches can feel noisy compared with hiding them. The AI pane and the preview pane compete for the same 440px slot. Tag and format colours depend on small swatches, so they are weak for colour-blind users without the text labels.
