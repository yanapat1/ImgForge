# `static/ts/datacenter/`: the Data Center page

The page at `?data` (all buckets), `?data=<bucket id>` and `?data=<bucket id>&path=<folder>` (design "Explorer",
`design/datacenter/design1`). `theme-boot.ts` sets `html[data-screen=data]` before the first paint, and `main.ts`
loads `app.js` on demand once the user is known, so the other screens never download this code. Server contract:
`dataviz/datacenter/API.md` (`/api/dc/*` and the assistant's `/api/llm/dc/*`), typed in `../types-datacenter.ts`.

| File | What it does |
|---|---|
| `app.ts` | `start()`: the header (Sessions / Data tabs, file search, settings, theme, user menu) and the 3-pane frame (tree, centre, details, AI drawer). It owns the routing (`navigate`: bucket and path go in the URL with `pushState`, and `popstate` goes back), the **one delegated click / change / input listener** (elements carry `data-act` / `data-change` / `data-input`, and every module exports its `*_ACTIONS` map), the keyboard (`/` search, Delete, F2 rename, Ctrl+A, Esc), the loads (buckets, summary and tags in parallel) and the header search. |
| `state.ts` | `D`, the one mutable state object (buckets, where we are, the listing, the selection, view choices, caches), and `hooks` (navigate / reload / render / selChanged / details), which `app.ts` fills in so the pane modules never import it. Also the format table (label and colour token per format), the format dot and badge, the tag chip, number and size formatters, and the pref keys. |
| `api.ts` | Typed wrappers of `/api/dc/*`, all through `core/api.ts`. |
| `tree.ts` | The left pane: All buckets, the buckets (format dot, source icon, count) with folders that expand (children come from `ls` on demand and are cached until the next reload), tags (a click filters the overview), the storage meter, and Import / Link source. Folder rows are drop targets. |
| `buckets.ts` | The All buckets overview: name filter, Tags menu, sort, cards / list, the summary line, format chips and cards (a sample mosaic, found once per bucket through `search`, plus the format badge, a warning line, counts and tags). A click focuses a card (its details show on the right); a double click or its name opens it. |
| `browser.ts` | The folder view: breadcrumb, Thumbnails / Names only (a pref), sort, name filter, New folder, Upload, Send to…, the folder strip (counts, tags, Edit tags, the format-change banner, upload progress), the bulk bar, the grid / list, and the search results. It stays fast on 20k-file folders: `ls` pages of 500 load as the scroll nears the end (a page is appended, never re-rendered), thumbnails (`?w=256`) load through an IntersectionObserver, and a selection change only flips classes. Click, Ctrl / Cmd, Shift ranges and checkboxes select. Dragging moves onto a folder tile, breadcrumb or tree row (Ctrl / Alt copies), and files dropped from the desktop are uploaded. |
| `details.ts` | The right pane: a bucket (source, detected format with its confidence and checks, Re-detect, tags, contents and split, sessions, Send), a folder, or the selection (preview stack, totals, pairing check, actions, Visualize N / Label N). Below 1100px it is an overlay. |
| `tags.ts` | The tag editor popover (`core/popover.ts` `floatPopover`): user chips, locked auto chips, a typeahead over `/api/dc/tags`, Create, suggestions, and Save, which sends `PUT …/tags` with the difference. With several items selected it only adds. |
| `ops.ts` | New folder, rename, move / copy (folder picker, optional new subfolder), delete (confirm, trash), and bucket rename / delete-or-unlink. Each one is a single `POST …/ops` batch followed by an action toast with Undo. A `retagged` answer gets the amber "Format changed: A → B (reason)" toast and the folder banner, and both can undo. |
| `upload.ts` | The Import data / Link source dialog (a new managed bucket filled with files, folders or a zip; a local folder through `/api/fs/browse`; an S3 bucket and prefix through a saved connection) and `uploadFiles` (XHR batches of ≤ 8 files / 16 MB with byte progress). |
| `send.ts` | Send to session: Visualize or Label, the session name, the task type (`label/state.ts` `TASK_TYPES`), a warning when no labels come along, the selected data, then `POST /api/dc/send` and a redirect to the new session. |
| `ai.ts` | The assistant drawer, shown only when the LLM is connected and the `data_center` feature is on (`data-llm`). It is a prompt bar when collapsed and a chat plus a scope and tools column when open. It streams the NDJSON of `/api/llm/dc/chat`: text, read-only tool runs as one collapsible card, a plan as a checklist with Confirm (`/api/llm/dc/confirm`, then a reload and any format-change toast) or Cancel, questions as option chips, and "can't do that" as a red-edged card with an alternative. Each bucket keeps its own chat history in memory. |

Styles: `static/css/datacenter.css`. Smoke test: `tests/test_dc_page.py`.
