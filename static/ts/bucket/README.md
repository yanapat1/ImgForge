# `static/ts/bucket/`: the Bucket page

The Bucket page at `?bucket` (all buckets), `?bucket=<bucket id>` and `?bucket=<bucket id>&path=<folder>` (design "Explorer",
`design/bucket/design1`). `theme-boot.ts` sets `html[data-screen=bucket]` before the first paint, and `main.ts`
loads `app.js` on demand once the user is known, so the other screens never download this code. Server contract:
`dataviz/bucket/API.md` (`/api/bucket/*` and the assistant's `/api/llm/agent/*`, `/api/llm/sessions*`), typed in `../types-bucket.ts`.

| File | What it does |
|---|---|
| `app.ts` | `start()`: the header (Sessions / Data tabs, file search, settings, theme, user menu) and the 3-pane frame (tree, centre, details, AI drawer). It owns the routing (`navigate`: bucket and path go in the URL with `pushState`, and `popstate` goes back), the **one delegated click / change / input listener** (elements carry `data-act` / `data-change` / `data-input`, and every module exports its `*_ACTIONS` map), the keyboard (`/` search, Delete, F2 rename, Ctrl+A, Esc), the loads (buckets, summary and tags in parallel) and the header search. |
| `state.ts` | `D`, the one mutable state object (buckets, where we are, the listing, the selection, view choices, caches), and `hooks` (navigate / reload / render / selChanged / details), which `app.ts` fills in so the pane modules never import it. Also the format table (label and colour token per format), the format dot and badge, the tag chip, number and size formatters, and the pref keys. |
| `api.ts` | Typed wrappers of `/api/bucket/*`, all through `core/api.ts`; the reads that can take a while (ls, search, detect, stats, …) go through `busy()` so the status bar names them. |
| `activity.ts` | The status bar at the bottom: one small line for the task in front (a failed upload, then a running upload / job, then a queued one) with stage, %, count, rate, time left, a 2px bar on its top edge and Cancel / Retry; `+N more` opens the list of every task (full rows) upwards. Polls `GET api/jobs`; card job badges (`jobBadge`). |
| `busy.ts` | Page work for the status line when no task runs: `busy(text, promise)` (shown after 250 ms) and the count of previews still loading. |
| `tree.ts` | The left pane: All buckets, the buckets (format dot, source icon, count) with folders that expand (children come from `ls` on demand and are cached until the next reload), tags (a click filters the overview), the storage meter, and Import / Link source. Folder rows are drop targets. |
| `buckets.ts` | The All buckets overview: name filter, Tags menu, sort, cards / list, the summary line, format chips and cards (a sample mosaic, found once per bucket through `search`, plus the format badge, a warning line, counts and tags). A click focuses a card (its details show on the right); a double click or its name opens it. |
| `browser.ts` | The folder view: breadcrumb + Copy path (`locationOf`: s3://… or the server folder; `core/dom.ts copyText` falls back to execCommand over plain http), Thumbnails / Names only (a pref), sort, name filter, Reload (`refresh`: buckets, tree and the folder; an S3 folder is listed again with `ls?refresh=1`), New folder, Upload, Send to…, the folder strip (counts, tags, Edit tags, the format-change banner, upload progress), the bulk bar, the grid / list, and the search results. It stays fast on 20k-file folders: `ls` pages of 500 load as the scroll nears the end (a page is appended, never re-rendered), thumbnails (`?w=256`) load through an IntersectionObserver, and a selection change only flips classes. Click, Ctrl / Cmd, Shift ranges and checkboxes select. Dragging moves onto a folder tile, breadcrumb or tree row (Ctrl / Alt copies), and files dropped from the desktop are uploaded. |
| `details.ts` | The right pane: a bucket (source, detected format with its confidence and checks, Re-detect, tags, contents and split, sessions, Send), a folder, or the selection (preview stack, totals, pairing check, actions, Visualize N / Label N). Below 1100px it is an overlay. |
| `tags.ts` | The tag editor popover (`core/popover.ts` `floatPopover`): user chips, locked auto chips, a typeahead over `/api/bucket/tags`, Create, suggestions, and Save, which sends `PUT …/tags` with the difference. With several items selected it only adds. |
| `ops.ts` | New folder, rename, move / copy (folder picker, optional new subfolder), delete (confirm, trash), and bucket rename / delete-or-unlink. Each one is a single `POST …/ops` batch followed by an action toast with Undo. A `retagged` answer gets the amber "Format changed: A → B (reason)" toast and the folder banner, and both can undo. |
| `upload.ts` | The Import data / Link source dialog (a new managed bucket filled with files, folders or a zip; a local folder through `/api/fs/browse`; an S3 bucket and prefix through a saved connection) (uploads go to `uploads.ts`). |
| `ctxmenu.ts` | Right-click menus like a desktop file manager: on a file / folder (it joins the selection), the folder's empty space (New folder, Upload, Refresh, view, sort, Copy path, Export, Send, Download / Update for a streamed S3 folder), a tree row, a bucket card / list row (the `bucketMenuItems` of `details.ts`) and the overview. Items are the normal `data-act` buttons plus `ctx-*` actions; opens at the pointer (`floatPopover` with `at`), the ContextMenu key / Shift+F10 too; inputs, the assistant and the editor keep the browser menu. |
| `resize.ts` | The splitters: the tree's right edge (`--dc-tree-w`) and the open assistant's top edge (`--dc-ai-rows`, the folder keeps 150 px). Pointer drag (one write per frame), arrow keys, double-click resets; saved in the prefs `dc_tree_w` / `dc_ai_h`. |
| `uploads.ts` | Background uploads: `queueUpload` returns at once; 4 requests in flight (batches of small files, chunks of big ones in parallel, resumable through `/upload/part`), adaptive chunk size for proxies, rows with MB/s, time left and finish clock in the status bar at the bottom, Cancel / Retry, a leave-page prompt. |
| `clip.ts` | Copy / Cut / Paste: Ctrl+C / Ctrl+X / Ctrl+V on the grid, right-click › Copy / Cut / Paste, the toolbar's Paste pill. The clipboard is `{bid, paths, cut}` (not the files). Same bucket: Cut = ops move, small Copy = ops copy; a folder, a big copy (≥ 200 MB) or another bucket: `POST /api/bucket/copy` (job `bk-copy`, the status bar), then a toast with Undo; Cut across buckets deletes the originals after. |
| `send.ts` | Send to session: Visualize or Label, the session name, the task type (`label/state.ts` `TASK_TYPES`), a warning when no labels come along, the selected data, then `POST /api/bucket/send` and a redirect to the new session. |
| `export.ts` | Export a folder: `downloadZip` (`GET …/export/check` first, so a failure is a toast with the reason, then an anchor so the zip streams) and Export to… (`openExportDialog`, from the Send to… menu and the bucket's Edit dialog): Download zip / S3 · RustFS / FTP / SFTP cards, a saved connection of that kind (else a link to Settings › Connections), for S3 a bucket combobox (`core/combobox.ts`, with Create bucket "x") and a prefix, for FTP / SFTP a path, Overwrite, and a live preview of the first file's destination (the folder layout is kept: `<prefix><path in the bucket>`). `POST …/export` starts a `bk-export:<bid>` job (the status bar shows it), then a toast gives the files and the URI. Remote targets need `bucket.manage`; the last choice is the `dc_export` pref. |
| `ai.ts` | The assistant drawer, shown only when the LLM is connected and the `bucket_data` feature is on (`data-llm`). Collapsed it is a prompt bar (`#bk-ai-q`: Enter opens the drawer and sends); open it is the shared chat (`core/chat.ts` `mountChat`, role `data`, mounted once and kept across repaints, textarea `#bk-ai-q`) plus a side column: the scope (bucket, folder, selection) and the tools from the agent's catalogue (`GET api/llm/agent/data/catalog`): which run on their own and which need your OK in the current mode, and the pending confirmations. The scope sent with every message is `{bucket, path, selection ≤ 500}`; History filters on `{bucket_id}`. A change the agent ran (a change / danger `tool_end`, an Undo) reloads the view (`hooks.reload`, coalesced) and a `retagged` result gets the format-change toast. |

Styles: `static/css/bucket.css`. Smoke test: `tests/bucket/test_bucket_page.py`.
